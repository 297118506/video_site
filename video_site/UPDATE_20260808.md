### 三、后端改动（[app.py](file:///D:/文件管理/VIDEO/video_site/app.py)）

#### 3.1 新增接口 `POST /api/openlist/multi_import`

**请求参数：**
```json
{
  "account": { "server_url": "...", "username": "...", "password": "...", "token": "..." },
  "files": [
    { "file_path": "/path/to/video1.mp4", "file_name": "video1.mp4" },
    { "file_path": "/path/to/video2.mp4", "file_name": "video2.mp4" }
  ],
  "category_id": 1,
  "cover_url": "https://...",
  "is_short_video": 0
}
```

**响应：**
```json
{
  "success": true,
  "imported_count": 2,
  "skipped_count": 0,
  "failed_count": 0,
  "imported": [
    { "name": "video1", "nfo_used": true },
    { "name": "video2", "nfo_used": false }
  ],
  "nfo_used": 1
}
```

#### 3.2 处理流程

对 `files` 数组中的每个文件：
1. 调用 `api.get_file_link()` 获取直链
2. 去重检查：若 `video_url` 已存在则计入 `skipped`
3. 默认使用原文件名作为标题
4. 调用 `_fetch_nfo_for_video()` 尝试解析同目录 NFO 文件：
   - 若存在 NFO，标题/描述/封面/分类/评分/年份/演员等字段优先使用 NFO 内容
   - NFO 封面优先级高于用户指定封面（与单个导入逻辑一致）
5. 调用 `create_video()` 写入数据库
6. 成功计入 `imported`，异常计入 `failed`

#### 3.3 与现有接口的对比

| 接口 | 用途 | 是否创建系列 | 标题来源 |
|------|------|------------|---------|
| `POST /api/openlist/single_import` | 导入单个视频 | 否 | 文件名 / NFO 标题 |
| `POST /api/openlist/multi_import` (新增) | 导入多个选中视频 | 否 | 文件名 / NFO 标题 |
| `POST /api/openlist/batch_import` | 导入整个目录 | 可选（按集数） | 目录名+集数 / NFO 标题 |

# 更新说明 - 2026-08-10 (二)

## 优化：「选择此目录」导入时的视频命名逻辑

**更新日期：2026-08-10**

---

### 一、优化背景

此前在 OpenList 管理中点击「选择此目录」批量导入视频时，**无论是否创建合集**，视频标题一律使用「目录名 第N集」格式。这导致用户取消「自动创建系列」后导入的视频仍被命名为"目录名 第1集"等，而非使用原文件名，不符合预期。

---

### 二、优化后的命名规则

点击「选择此目录」导入目录中的视频时：

| 场景 | 视频标题 | 示例 |
|------|---------|------|
| **创建合集**（勾选「自动创建系列」且有 2+ 视频） | `{目录名} 第{N}集` | `电影A 第1集`、`电影A 第2集` |
| **创建合集**（勾选但目录仅 1 个视频） | `{目录名}` | `电影A` |
| **不创建合集**（取消勾选「自动创建系列」） | **原文件名** | `EP01.mp4`、`正片.mp4` |
| **存在 NFO 文件** | **NFO 标题**（优先级最高，覆盖以上规则） | NFO 中定义的标题 |

---

### 三、代码改动（[app.py](file:///D:/文件管理/VIDEO/video_site/app.py#L958-L966)）

`api_batch_import` 函数中，将标题判断条件由 `if series_name:` 改为 `if series_id:`：

```python
# 优化前（旧逻辑）：
if series_name:                    # ← series_name 始终非空，导致不创建系列时也用目录名
    if len(videos) > 1:
        base_title = f"{series_name} 第{idx}集"
    else:
        base_title = series_name
else:
    base_title = name

# 优化后（新逻辑）：
if series_id:                      # ← 仅在真正创建合集时才用目录名
    if len(videos) > 1:
        base_title = f"{series_name} 第{idx}集"
    else:
        base_title = series_name
else:
    base_title = name              # ← 不创建合集时使用原文件名
```

**原因**：前端点击「选择此目录」时始终把目录名作为 `series_name` 传入，但 `series_id` 仅在 `auto_create_series=True` 且实际创建系列后才会被赋值。用 `series_id` 作为判断条件能准确区分"是否创建了合集"。

---

### 四、不受影响的部分

- **NFO 标题优先级不变**：若视频所在目录存在 NFO 文件，NFO 中的标题始终覆盖上述命名（`video_data['title'] = metadata['title']`）
- **单个视频导入（`single_import`）**：始终使用原文件名（或 NFO 标题），不受本次改动影响
- **多选视频导入（`multi_import`）**：始终使用原文件名（或 NFO 标题），不受本次改动影响
- **封面优先级**：NFO 封面 > 用户指定封面，不变
- **合集创建逻辑**：仍由「自动识别并创建系列」复选框控制，不变
